# 项目展示与简历说明

## 项目定位

本项目要证明的不是“会调用一个测试工具”，而是能够把接口测试中的执行、依赖、数据传递、
断言和安全边界做成可复用的工程能力。

当前完成版本的核心展示点：

1. 运行级变量通过 `{{variable_name}}` 在路径、请求头、查询参数、JSON 请求体和断言中复用。
2. 前序 JSON 响应按路径提取数据，后续用例通过显式依赖形成业务链路。
3. 完整占位符保留整数、布尔值、列表等 JSON 类型，避免把所有测试数据错误地字符串化。
4. 缺失变量、提取失败、依赖失败和网络错误使用结构化状态与错误码表达。
5. 网络目标默认拒绝，本地演示也要显式开启；敏感变量不会在执行结果中返回其值。
6. 使用标准库 SQLite 保存已脱敏结果，提供稳定运行 ID、UTC 时间、摘要列表和详情查询。
7. 中文控制台可以一键运行链路、刷新最近记录并重新打开历史详情。
8. 将 OpenAPI 3.0/3.1 JSON 对象确定性转换为现有执行器可校验的基础正向用例草稿，
   并通过警告和跳过统计显式呈现不支持或无法生成的操作。
9. 从已脱敏历史结果生成独立静态 HTML 报告，通过 CSP、HTML 转义、长度限制和无外部资源设计
   降低离线报告的注入与数据泄露风险。

## 面试现场演示顺序

演示前只使用仓库自带的本地接口和虚构数据，不连接真实业务或生产环境。

1. 展示 `contracts/test-run-v0.2.yaml`，说明先冻结跨模块契约再由多个 Agent 并行开发。
2. 不开启本地目标开关提交示例，展示默认拒绝的目标策略。
3. 在服务进程中设置 `ALLOW_LOCAL_TARGETS=true` 后重新启动。
4. 提交 `examples/demo-run.json`，解释第一个用例如何提取 `user_id`、`user_name`。
5. 展示第二个用例的 `depends_on`、路径模板、查询参数模板和断言模板。
6. 指出响应只包含 `extracted_variables` 名称，不包含提取值和请求头。
7. 在中文控制台刷新“最近运行”，打开刚产生的记录，说明数据库只保存安全结果模型。
8. 在中文页面的 OpenAPI 区域加载合成演示，也可粘贴 JSON 或选择不超过1 MiB 的 `.json` 文件。
9. 点击“生成基础用例”，查看生成数、跳过数和结构化 warning，说明页面只支持 JSON、不支持 YAML。
10. 人工点击“载入测试编辑器”，展示路径参数、查询参数、JSON 请求体和本地 `$ref` 生成的草稿；
    强调载入不会自动执行，仍需检查后手动点击“运行测试”。
11. 说明原始文档和生成草稿只存在页面内存、不写入浏览器存储，输入中不得放真实密钥；后续运行
    仍经过目标 SSRF 白名单策略。
12. 在“最近运行”点击“下载报告”，离线打开 HTML 文件，展示汇总、用例状态、断言与错误信息；
    说明报告只读取已脱敏历史结果，不包含请求配置、变量值或原始响应。
13. 运行全量 Pytest，并以现场输出说明测试数量和覆盖率。

启动与请求命令见仓库根目录 `README.md`。如果任何一步没有通过，应如实解释当前缺陷，
不要使用预先录制的成功结果替代验证。

只有在相应功能已经由代码和测试验证后，才可使用以下表述：

> 设计并实现顺序接口自动化测试执行器，支持运行级变量、响应 JSON 路径提取、
> 显式用例依赖及路径/请求/断言模板化，覆盖缺失变量、提取失败和依赖跳过等失败路径。

> 为测试目标加入默认拒绝的 origin 白名单策略和显式本地开发开关，关闭重定向及环境代理继承，
> 并对秘密变量、请求头和网络异常进行集中脱敏，降低 SSRF 与敏感信息泄漏风险。

> 使用 Python 标准库 SQLite 实现本地运行历史，支持 UUIDv4 运行标识、UTC 时间、摘要列表、
> 详情查询、稳定错误映射及500条自动保留，并限制持久化边界为已脱敏结果模型。

> 基于已脱敏运行历史生成无脚本、无外部资源的独立 HTML 测试报告，对动态内容统一执行长度限制
> 和 HTML 转义，并通过 CSP、禁止缓存及固定 UUID 文件名控制离线报告的安全边界。

## 面试追问准备

### 为什么采用顺序执行而不是 DAG 并发？

当前目标是确定性表达登录、提取令牌、查询资源等线性业务链路。顺序执行更容易保证变量发布
时机和失败语义；DAG 调度、并发隔离和资源控制属于后续范围。

### 为什么依赖和变量引用要同时存在？

`depends_on` 表达业务语义和失败传播；模板引用负责数据传递。只依靠变量是否存在，无法清晰表达
一个用例为什么应被跳过，也不利于生成可读报告。

### 为什么提取要原子发布？

如果多个提取规则只成功一部分就写入运行上下文，后续用例可能使用半完整状态。只有断言和所有
提取规则都通过后统一发布，可以保证后续读取到一致的数据。

### AI 在项目里扮演什么角色？

当前版本的结果判定完全由确定性断言完成。未来 AI 可以辅助生成边界场景或总结失败日志，
但生成内容必须经过规则校验和人工确认，不能让模型直接决定测试是否通过。

## 诚实展示边界

- 当前 API 无认证，只用于可信本地开发，不对公网开放。
- 当前目标策略按配置的 origin 和本地主机名判断，不等同于完整的企业级网络隔离。
- 当前只支持 JSON 响应提取和点分隔路径，不支持 JSONPath 全语法。
- 当前用例按提交顺序串行执行，不提供任务队列或并发调度。
- 当前历史使用本机 SQLite，最多保留500条，不提供多用户隔离、筛选、删除或备份。
- 未声明为 secret 的断言值可能进入历史；敏感变量必须显式加入 `secret_variables`。
- OpenAPI 生成器只接受请求内的 OpenAPI 3.0/3.1 JSON 对象，不下载远程文档、不解析外部 `$ref`，
  不生成认证凭据、负向或边界用例，也不直接执行生成结果。
- OpenAPI 生成器为每个 operation 设置2048个 Schema 节点预算，并把单条生成用例的 UTF-8
  序列化结果限制在256 KiB，超限操作会被跳过并返回结构化 warning。
- OpenAPI 文档中的 server 地址在生成阶段不会被访问；生成结果后续提交执行时仍受目标 SSRF
  白名单和本地开发开关约束。
- 中文页面只接受 OpenAPI JSON，不支持 YAML；文档与生成草稿只保存在页面内存，刷新即丢失。
  生成和载入都不会自动执行，且输入文档和示例中不得包含真实密钥。
- HTML 报告只包含已保存的 `TestRunResult`，不提供原始请求/响应流量审计、PDF、Allure、发送、
  模板自定义或报告签名；未声明为 secret 的断言值仍可能随历史结果进入报告。
- 当前提交的全量测试结果为 `171 passed`，分支覆盖率为 `90.65%`；代码变化后必须以重新运行
  测试得到的指标为准。
- 项目指标必须来自当前提交对应的测试输出，不能沿用旧版本数字。
