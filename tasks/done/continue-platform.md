# continue-platform — 重新审议并推进接口测试平台第二阶段

状态：DONE

创建日期：2026-07-25

## 目标

把第一阶段的单接口执行器推进为可表达真实业务链路的顺序测试执行器：用户可以提供运行级变量，
从前序响应提取数据，并在后续请求和断言中引用；同时补上网络目标与敏感数据的最低安全控制。

## 范围

- 重新审计当前后端、测试、安全和多 Agent 工作区基线。
- 定义运行变量、模板替换、响应提取和顺序依赖契约。
- 在 `src/app/**` 实现第二阶段执行能力和必要安全控制。
- 在 `tests/**` 覆盖正常链路、缺失变量、提取失败、类型保留和安全边界。
- 更新示例、README 和验证记录。

## 非范围

- 数据库持久化、Web 前端、用户登录与多租户授权。
- OpenAPI 导入、Allure、任务队列、并发执行和大模型能力。
- 连接真实生产系统、部署、发布或推送远程仓库。

## 验收标准

- [x] 运行级变量可用于路径、请求头、查询参数、JSON 请求体和断言期望值。
- [x] 前序响应可按 JSON 路径提取变量，供后续用例使用。
- [x] 完整占位符保留原始 JSON 类型，嵌入字符串的占位符执行字符串化。
- [x] 缺失变量和提取失败产生结构化用例失败，不发送依赖不完整的请求。
- [x] 结果只报告提取变量名称，不泄漏提取值或请求头。
- [x] 网络目标安全策略有明确默认值、测试和本地演示配置。
- [x] 全量 Pytest、覆盖率和工作区验证通过。
- [x] README 与示例准确反映第二阶段能力。

## 风险与假设

- 当前 API 无身份认证，仅适合本地开发演示，不对公网部署。
- 任意网络目标会带来 SSRF 风险；本阶段必须加入默认限制并保留显式本地开发开关。
- 变量可能包含令牌；响应结果和错误信息不得包含变量值或完整敏感头。
- 用例按提交顺序串行执行，后续阶段再考虑 DAG 和并行。

## 子任务交接

- `backend_audit`：只读架构审计；禁止修改；返回数据模型、执行语义和文件建议。
- `tester_audit`：只读测试审计；禁止修改；返回测试矩阵、边界与验收命令。
- `security_audit`：只读安全审计；禁止修改；返回 SSRF、敏感数据和资源限制建议。
- `backend_impl`：按冻结契约修改 `src/app/**` 与 `.env.example`；不得修改测试、文档或任务卡。
- `tester_impl`：按冻结契约修改 `tests/**`；不得修改实现、文档或任务卡。
- `docs_impl`：按冻结契约修改 README、examples 和 docs；不得修改实现、测试或任务卡。

## 主 Agent 决策

- 采用 `{{variable_name}}` 模板语法；本阶段不支持转义。
- 用例 ID 可省略以兼容 v0.1，省略时按顺序生成 `case_1` 等稳定 ID。
- 接口依赖必须显式引用前序用例；变量引用仍会在缺失时阻止请求。
- 仅支持 JSON 响应提取，禁止覆盖已有变量。
- 只有断言和提取均通过时才原子发布提取变量。
- `assertion.expected` 支持模板，并对秘密值执行集中脱敏。
- 默认目标白名单为空；本地演示通过 `ALLOW_LOCAL_TARGETS=true` 显式开启。
- 修复 `json_equals` 缺少 path 仍被接受的校验缺陷。
