# task-oriented-console — 任务导向测试控制台重构

状态：DONE

创建日期：2026-07-30

## 目标

将按技术模块堆叠的长页面重构为按用户任务推进的五步工作台，让首次使用者能够清楚理解
“导入文档、生成方案、审核候选、执行测试、查看记录”的顺序和当前下一步操作。

## 范围

- 增加可跳转的五步流程导航、当前状态和下一步提示。
- 重构 OpenAPI 与 AI 生成区域的说明、层级和视觉关联。
- 将候选用例改为紧凑摘要卡片，按需展开编辑，减少长页面滚动。
- 优化运行配置、结果和历史区域的状态表达与移动端布局。
- 保留所有现有元素 ID、API 调用、安全校验和人工确认边界。
- 补充任务流程、可访问性、桌面端和移动端测试。

## 非范围

- 修改后端 API、数据库、执行器或 AI Provider 行为。
- 增加前端构建框架、第三方 UI 库或新生产依赖。
- 自动运行测试、自动接受 AI 候选或保存浏览器状态。
- 在本任务中配置真实 API Key。

## 验收标准

- [x] 页面明确展示五步流程，并支持键盘和锚点跳转。
- [x] 首屏能解释平台用途、当前 Provider 和推荐下一步。
- [x] OpenAPI 原始 JSON 默认可折叠，生成入口和输入状态仍易发现。
- [x] OpenAPI 与 AI 候选之间的差异和作用在页面上可直接理解。
- [x] 候选卡片默认紧凑，展开后保留全部安全编辑能力。
- [x] 运行和结果区域在桌面双栏下无溢出或遮挡；移动端按用户要求仅保留基础防溢出。
- [x] 所有既有功能测试、全量测试和分支覆盖率质量门通过。

## 风险与假设

- 页面仍为无构建依赖的原生 HTML/CSS/JavaScript，需要控制单文件复杂度。
- 旧测试依赖部分稳定 ID；重构必须保持这些 ID 和现有 API 行为。
- 候选内容可能很长，摘要视图必须允许键盘展开且动态文本只能使用安全 DOM API。
